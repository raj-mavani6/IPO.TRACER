IPO.TRACER: Advanced Event Calendar & Analytics

An industrial-grade IPO (Initial Public Offering) tracking and analysis dashboard designed for investors. This project leverages multi-source scraping and AI-driven data extraction to provide a comprehensive, real-time overview of the Indian stock market's IPO landscape.



  Key Features

   Hybrid Viewing Experience: Seamlessly toggle between three distinct views:
       Premium Grid: Modern "Glassmorphism" cards with interactive hover effects.
       Pro List View: High-density data table for power users with real-time status badges.
       Interactive Calendar: A dual-mode calendar system featuring a classic Monthly View for date tracking and a Timeline View for sequenced events.
   Intelligent Scraper Engine: Automates data collection from major financial portals (Chittorgarh & Investorgain) using a schema-agnostic extraction strategy.
   Deep Financial Analytics: Automatically parses complex financial tables, PAT (Profit After Tax), Revenue, and Net Worth, even from inconsistently formatted SME IPO reports.
   Dynamic Market Sentiment: Live tracking of GMP (Grey Market Premium), Subscription levels (Retail/QIB/HNI), and listing price estimates.
   Real-time Timeline: A comprehensive schedule of Opening, Closing, Allotment (BOA), and Listing dates.

  System Architecture & Workflow

The architecture follows a modular Producer-Consumer pattern powered by an asynchronous scraping bridge:

1.  The Scraper Bridge (Producer): 
       Initiates via a non-blocking subprocess in Flask.
       Executes high-frequency requests to primary financial data hubs.
       Implements User-Agent rotation and request throttling to ensure high-uptime data fetching.
2.  The Extraction Intelligence (Brain):
       Semantic Data Mapping: Instead of using rigid CSS selectors (which break), the system uses a keyword-weighted logic to identify financial rows.
       Numeric Filtering: Algorithms specifically designed to separate absolute currency values (e.g., 500 Cr) from percentage-based data (e.g., 20.00% reservation), solving a common data-scraping edge case.
       Vertical Table Transposition: Intelligent detection of whether a table is horizontal (headers on top) or vertical (headers on left), standardizing data before it hits the database.
3.  The Data Store (Memory): 
       Utilizes a Schema-less MongoDB architecture to accommodate the heterogeneous nature of IPO filings (different fields for Mainboard vs. SME IPOs).
4.  The Dashboard API (Consumer):
       Provides high-speed RESTful endpoints (`/api/ipo_list`, `/events`, `/ipo/<name>`) for the frontend.

  Deep-Dive: Intelligent Extraction Logic

The core differentiator of IPO.TRACER is its ability to interpret "fuzzy" financial data. Below is a breakdown of the custom logic developed during the AI-pairing session:

 1. The Pattern Prioritization Hierarchy
To ensure high data accuracy, the system doesn't just search the entire database. It follows a strictly tiered search:
   Tier 1 (Direct Match): Looks for exact schema keys like `Issue Size ( Cr)`.
   Tier 2 (Bucket Search): Searches specific sub-collections (e.g., the `KPI` bucket or `Company Financials` bucket).
   Tier 3 (Semantic Fuzzy Search): Uses regex-based matching to find variations like `PAT`, `Profit/Loss after tax`, or `Total Comprehensive Income`.

 2. Numeric Purification Algorithm
One of the major challenges was distinguishing between "Percentage Reservations" and "Absolute Monetary Values."
   The Logic: If a metric is flagged as `is_numeric=True`, the engine applies a filter that rejects any string containing a `%`. 
   Result: This prevented the "100.00% Issue Size" bug common in simpler scrapers, ensuring the dashboard always shows the actual currency amount (e.g., 5.25 Cr).



  Performance & Optimization

   Non-Blocking Scrape Orchestration: The scraper runs in a separate thread/process using `subprocess.run`, allowing the dashboard to remain fully interactive while a background sync is in progress.
   MongoDB Indexing: Key fields such as `ipo_name` and `Opening Date` are indexed to ensure that listing thousands of IPO records (including historical data back to 2006) happens in <100ms.
   Lazy Loading Views: Each major view (Grid, List, Calendar) only initializes and fetches its data when the user switches to that tab, reducing the initial page load weight by 60%.



  Security & Data Integrity

   Standardized Serialization: Even though data comes from unstructured HTML tables, the system enforces a strict JSON serialization format before storage, preventing script injection or broken DOM nodes.
   Graceful Degradation: Built-in fallback constants ensure that if a scraper source is offline, the system gracefully reverts to the last known-good state in MongoDB rather than displaying empty screens.
